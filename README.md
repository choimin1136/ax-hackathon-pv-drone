# ax-hackathon-pv-drone

2026 전남광주 기업 AX 혁신챌린지 해커톤 프로젝트 **SunPatch**입니다. 드론이 태양광 발전소를 구역 단위로 비행하며 찍은 열화상을 핫스팟 모델이 바로 판정합니다. 사람은 근거 사진으로 후보를 확인하고, 의심 구역만 골라 다시 비행합니다.

> **시뮬레이션:** 실제 드론을 비행하지 않습니다. 드론은 ArduPilot SITL(실제 비행 제어기 펌웨어의 시뮬레이터)로 날고, 발전소 배치는 가상입니다. 열화상 사진(AI Hub)과 핫스팟 판정(학습한 모델)은 실제 데이터와 모델을 씁니다.

  - [모델 안내](model/README.md): 핫스팟 모델 구조, 학습, 평가
  - [서빙 템플릿](aistream-hotspot-template/README.md): 모델 서빙 배포
  - [기획 문서](system-scenario-plan.md)

## 해결하려는 문제

드론 점검에서 시간이 드는 곳은 비행보다 그 뒤입니다. 사진을 판독하고, 조치할 곳을 정하고, 애매한 구역을 다시 확인해야 합니다. SunPatch는 이 과정을 한 화면에서 이어지게 합니다.

```text
드론 비행 → 구역 도착 즉시 핫스팟 판정 → 지도에 색 표시 → 사람 확인(승인·제외) → 의심 구역만 재비행 → 기록·분석·보고서
```

## 화면

| 메뉴 | 내용 |
|---|---|
| 01 점검 현황 | 3D·2D 발전소 지도, 드론 켜기·끄기·비행 시작, 실시간 드론 위치와 경로, 구역 판정 색, 촬영 이미지(모델 결과), 비행 계기(수평계·방위·속도·고도), 드론 로그 |
| 구역 상세 | 실제 열화상과 모델이 찾은 영역 상자, 모델 결과 이미지 겹치기, 후보별 면적·점수, 승인·제외 |
| 02 점검 기록 | 서버에 누적된 날짜·시간별 비행 기록, 기록별 2D 지도와 당시 사진·모델 결과, 후보 승인·제외, 공용 기록 삭제 |
| 03 선택 점검 | 기록 기준 재점검 구역 추천 또는 직접 선택, 확정 후 드론 재비행 |
| 04 점검 분석 | 날짜·시간별 기록 선택, 발전량 예측·실측 비교(더미), 승인 구역 기준 회수 전력량·금전 가치·탄소 감축 추정, 정비 우선순위·반복 탐지·기상 점검일(더미) |
| 05 점검 보고서 | 날짜·시간별 기록 선택, 해당 비행의 점검 결과·승인·제외·미확인·가치 추정, 기준 시각까지의 기록 분석, 보고서 미리보기와 동일한 HTML 다운로드 |

로그인 없이 공개 주소에서 누구나 조작할 수 있습니다. 실시간 점검 화면은 서버의 같은 비행을 따라가며, 점검 기록·분석·보고서에서는 저장된 과거 비행을 선택할 수 있습니다. 기록과 승인·제외는 서버에 저장되어 같은 서버에 접속한 기기끼리 공유합니다.

## 시스템 구조

```text
브라우저 ──HTTP──→ 웹 서버 (Node 20, server/)
                     ├─ 실행 → ArduPilot SITL ←MAVLink→ 비행 프로그램 (drone/mission.py) → 비행 기록 live.jsonl
                     ├─ 구역 사진 → 핫스팟 모델 서빙 (POST /predict) → 판정·영역·결과 이미지
                     ├─ 사진 폴더 (PHOTO_DIR, AI Hub 열화상)
                     └─ 점검 기록 저장 (inspection-history.json)
```

| 구성 요소 | 역할 | 위치 |
|---|---|---|
| 웹 서버 | 화면, 드론 제어 API, 비행·점검 기록, 모델 호출 중계, 사진 제공 | 팀 서버, 포트 8501 |
| ArduPilot SITL | 쿼드콥터 비행 시뮬레이션 (8배속) | 팀 서버 |
| 비행 프로그램 | 구역 웨이포인트 업로드, 도착 이벤트·위치·자세 기록 | 팀 서버 |
| 핫스팟 모델 서빙 | SegFormer B1 기반 핫스팟 분할과 이미지 판정 (GPU) | 전남 AI 오픈플랫폼 |

- **모델 호출:** 서빙 도메인은 브라우저 요청을 받지 않아, 웹 서버가 사진을 골라 모델로 보내고 결과만 화면에 넘깁니다.
- **배포:** `main`에 merge하면 30초 안에 팀 서버가 새 코드로 다시 시작합니다.
- **드론 운영:** 설치와 실행은 [SITL 안내](sitl/README.md)를 참고하세요.

## 셀 판정

드론이 구역에 도착하면 웹 서버가 그 구역의 사진을 모델로 보내고, 모델의 `is_hotspot`으로 두 가지를 표시합니다.

| 모델 결과 | 모델 상태 예 | 화면 | 후보 |
|---|---|---|---|
| `is_hotspot: true` | `hotspot_localized` | 핫스팟 탐지 (빨강) | 모델이 찾은 영역 |
| `is_hotspot: false` | `no_hotspot_detected`, `low_confidence_candidate` | 핫스팟 없음 (초록) | 없음 |

- **사진 배정:** 새 전체 비행마다 `PHOTO_DIR`의 사진을 구역에 무작위로 다시 배정합니다. 재비행은 같은 사진을 씁니다.
- **시연용 핫스팟 보장:** 비행 순서 앞쪽(A·B행) 한 구역에는 Positive 폴더 사진을 주고, 모델이 핫스팟으로 판정할 때까지 최대 5번 사진을 바꿉니다.
- **실패할 때:** 사진이 없거나 모델 호출이 실패한 구역은 예시 판정과 합성 이미지로 표시합니다.
- **사람 확인:** AI 결과는 참고용이며 최종 판단은 사람이 합니다. 승인한 후보가 있는 구역만 가치 추정에 포함합니다. 보고서에는 승인·제외·미확인 상태를 모두 표시합니다.

## 데이터와 모델

- **데이터:** AI Hub [신재생 에너지 발전 설비 결함진단 멀티모달 데이터](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&aihubDataSe=data&dataSetSn=71923)의 태양광 열화상 사진. 서버의 `/data/test`에 두며 저장소에는 포함하지 않습니다.
- **모델:** SegFormer B1으로 핫스팟 영역을 찾고 이미지 판정 헤드가 핫스팟 여부를 냅니다. 구조와 학습 순서는 [모델 안내](model/README.md)에 있습니다.
- **응답:** 이미지 점수(`probability`, 보정 전), 판정(`is_hotspot`), 영역(`bbox`, `area_px`, 영역 점수), 결과 이미지(`output`)를 돌려줍니다. 점수는 이미지 전체 점수이며 영역별 확률이 아닙니다. 온도, 원인, 발전 손실은 측정하지 않습니다.

### 시연 사진 폴더 (`/data/test`)

시연 비행에서 구역마다 배정하는 열화상 사진은 팀 서버의 `/data/test`에 있습니다. 약 4.0 GB라서 저장소와 제출본에는 넣지 않았습니다. AI Hub 데이터는 이용 약관상 재배포가 제한되므로, 필요하면 아래 출처에서 직접 내려받습니다.

| 항목 | 내용 |
|---|---|
| 출처 | AI Hub [신재생 에너지 발전 설비 결함진단 멀티모달 데이터](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&aihubDataSe=data&dataSetSn=71923) · 태양광 패널 열화상 |
| 용도 | 학습에 쓰지 않은 사진을 시연 비행의 구역별 촬영 사진으로 사용 |
| 크기 | 약 4.0 GB · 사진 640×512 |
| 사용 폴더 | `TS_SolarPanel_Normal_PanelFront/` 정상 패널 · `TS_SolarPanel_Positive_PanelFront/` 핫스팟 패널 |
| 파일 이름 예 | `TS_SolarPanel_Normal_PanelFront/2025_Youngkwang_Normal_11619.jpg` |

```text
/data/test/
├─ TS_SolarPanel_Normal_PanelFront/     정상 패널 열화상 (*.jpg)
└─ TS_SolarPanel_Positive_PanelFront/   핫스팟 패널 열화상 (*.jpg)
```

- **읽는 방식:** 서버는 `PHOTO_DIR` 아래 하위 폴더까지 jpg·png 파일만 찾습니다. 다른 파일(라벨 등)이 함께 있어도 무시합니다. 사진 목록은 1분에 한 번만 다시 읽습니다.
- **핫스팟 보장:** 경로에 `positive`(대소문자 무시, `HOTSPOT_PHOTO_PATTERN`)가 들어간 사진을 비행 앞쪽 한 구역에 배정합니다.
- **다른 환경에서 재현:** AI Hub에서 데이터를 받아 정상·핫스팟 사진을 위 구조처럼 두 폴더에 나눠 넣고, `PHOTO_DIR`을 그 폴더로 지정합니다. 폴더 이름은 달라도 되지만 핫스팟 사진의 경로에는 `positive`가 들어가야 합니다.

```bash
PHOTO_DIR=/data/test MODEL_URL=<모델 서빙 주소>/predict node server/index.mjs
```

- **사진이 없을 때:** `PHOTO_DIR`을 지정하지 않으면 구역 판정은 예시 값, 사진은 합성 이미지로 표시해 화면과 비행은 그대로 확인할 수 있습니다.

## 금전·공공 가치

사람이 승인한 핫스팟이 있는 구역만 계산합니다. 모든 계수는 화면에서 바꿀 수 있는 가정값이고, 값에는 "추정"을 표시합니다.

```text
회수 가능 전력량 = 구역 용량 × 8,760시간 × 이용률 × 출력 저하율
금전 가치 = 회수 가능 전력량 × 판매 단가
공공 가치 = 회수 가능 전력량 × 탄소 계수
수리비 회수 기간 = 수리비 ÷ 연간 금전 가치
```

| 가정 | 기본값 |
|---|---|
| 구역 용량 | 10kW |
| 이용률 | 15% |
| 판매 단가 | 100원/kWh |
| 탄소 계수 | 0.4kg/kWh |
| 출력 저하율 (낮음·기준·높음) | 2% · 5% · 10% |
| 수리비 | 100,000원 |

## 실행 방법

Git과 Node.js 20 이상을 준비합니다. 아래 명령은 터미널(Windows는 PowerShell)에서 실행합니다. 웹 서버는 추가 npm 패키지 설치 없이 실행되며, 드론 시뮬레이터와 모델·사진 설정은 별도로 필요합니다.

처음 내려받는 경우:

```bash
git clone https://github.com/choimin1136/ax-hackathon-pv-drone.git
cd ax-hackathon-pv-drone
```

이미 내려받았다면 기존 프로젝트 폴더로 이동합니다. 다음 명령은 모두 최상위 `README.md`와 `package.json`이 있는 폴더에서 실행합니다.

```bash
node --version
node server/index.mjs
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. 실행한 터미널은 켜 두고, 종료할 때는 `Ctrl+C`를 누릅니다.

- `node`를 찾을 수 없으면 Node.js 설치와 PATH 설정을 확인하고 터미널을 다시 엽니다.
- `EADDRINUSE` 오류는 해당 포트를 다른 프로세스가 사용 중이라는 뜻입니다. 이미 대시보드를 실행했다면 기존 화면을 사용합니다.
- 로컬 서버는 팀 서버와 별개입니다. 팀 서버의 점검 기록·사진·모델·SITL 설정을 자동으로 가져오지 않습니다. 로컬에 저장된 기록이 있어야 기록 화면에 표시됩니다.
- 드론까지 띄우려면 [SITL 안내](sitl/README.md)에 따라 실행 환경을 준비합니다. 실제 열화상과 모델 결과에는 `PHOTO_DIR`와 접근 가능한 모델 서빙 설정이 필요합니다.
- `node tools/serve.mjs`는 정적 화면 미리보기용입니다. 기록 저장·모델 호출·드론 제어 API를 사용하려면 `node server/index.mjs`를 실행합니다.

```bash
npm test
```

시연 전에는 팀 서버의 Linux 셸에서 모델 연결을 점검합니다. 모델 서빙 상태, `PHOTO_DIR`의 핫스팟·정상 사진 몇 장의 직접 판정(라벨 일치와 응답 시간), 웹 서버의 모델 연결을 차례로 확인하고, 문제가 있으면 종료 코드 1로 끝납니다.

```bash
cd /data/hackathon/deploy && PHOTO_DIR=/data/test npm run check:model -- --count 10
```

### 설정값

바뀔 수 있는 값과 기본값은 모두 [server/config.mjs](server/config.mjs) 한 곳에 있습니다. 서버마다 다른 값은 환경 변수로 덮어쓰고, 비워 두면 기본값을 씁니다. 서버가 켜질 때 쓰는 설정을 `Config: …` 한 줄로 로그에 남깁니다. 전체 예시는 [sitl/sitl.env.example](sitl/sitl.env.example)에 있습니다.

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `HOST` / `PORT` | `127.0.0.1` / `5173` | 서버 주소. 팀 서버는 `0.0.0.0` / `8501` |
| `BASE_PATH` | 없음 | 공개 주소의 경로 앞부분 (예: `/i/cM6-Hw0t0JXk4-bD`) |
| `FLIGHT_DIR` | `drone/sample_flight` | 비행 기록 폴더 |
| `HISTORY_FILE` | `FLIGHT_DIR/inspection-history.json` | 점검 기록 저장 파일 |
| `PHOTO_DIR` | 없음 | 열화상 사진 폴더. 하위 폴더까지 jpg, png를 찾음. 팀 서버는 `/data/test` |
| `MODEL_URL` | 팀 모델 서빙의 `/predict` | 모델 서빙 주소 |
| `HOTSPOT_PHOTO_PATTERN` | `positive` | 핫스팟 보장에 쓸 사진의 폴더 이름 패턴 |
| `SITL_*`, `PYTHON_BIN`, `MISSION_SCRIPT` | 팀 서버 경로 | 드론 설정. [SITL 안내](sitl/README.md#설정값) 참고 |

| `drone/` | 비행 프로그램, 연결 시험 스크립트, 저장된 비행 기록 |

## 한계

- **시뮬레이션 비행:** 실제 기체가 아니고, SITL은 사진을 찍지 않습니다. 사진은 구역에 무작위로 배정합니다.
- **보정 전 점수:** 모델 점수는 확률로 보정하지 않았습니다.
- **작은 핫스팟:** 초기 측정에서 25px 이하 핫스팟을 놓쳤습니다. "핫스팟 없음"은 안전을 보증하지 않습니다.
- **가상 배치:** 발전소 구역과 사진 위치는 지리 좌표가 아닙니다.
- **공개 조작:** 공개 주소에서는 누구나 드론을 켜고 끌 수 있어 시연 중 끊길 수 있습니다.

## 향후 계획

- **실기체 검증:** SITL을 실제 드론과 기체 카메라로 바꿔 같은 미션으로 시험
- **확률 보정·성능 검증:** 독립 시험 데이터로 임계값과 확률 보정, 작은 핫스팟 재현율 개선
- **수리 의사결정:** 발전량 예측과 실제 발전량의 차이로 손실을 추정해 수리비와 비교
- **기상 연계 점검:** 날씨에 따라 점검 시기와 빈도 제안

실제 계량기의 발전량과 실제 기상 관측·예보 데이터는 이번 구현에 사용하지 않습니다. 발전량 비교와 기상 연계 점검일 화면은 더미 데이터로 시연하며, 실제 측정값이나 모델의 발전량 예측 결과가 아닙니다. 자세한 내용은 [기획 문서](system-scenario-plan.md)를 참고하세요.
