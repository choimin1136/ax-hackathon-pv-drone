# ax-hackathon-pv-drone

2026 전남광주 기업 AX 혁신챌린지 해커톤 프로젝트입니다. 드론이 태양광 발전소를 셀 단위로 비행하며 보낸 열화상 사진에서 핫스팟 후보를 찾아, 어느 셀을 먼저 확인하고 다시 점검할지 알려 주는 플랫폼을 만듭니다.

> **상태:** 개발 중. 아래 기능은 구현 계획이며, 완료된 항목은 구현 현황에 표시합니다.
>
> **시뮬레이션:** 실제 드론을 비행하지 않습니다. 발전소 격자와 비행은 가상이고, 열화상 사진과 탐지 결과는 실제 데이터와 모델을 사용합니다.

## 해결하려는 문제

드론 점검에서는 사진을 판독하고, 조치할 곳을 정하고, 애매한 구역을 다시 확인하는 데 시간이 듭니다. 이 프로젝트는 다음 흐름으로 이 과정을 줄이는 것을 목표로 합니다. 현장 수치는 아직 검증 중입니다.

```text
비행 → 핫스팟 분석 → 셀 판정 → 사람 확인 → 애매한 셀만 재비행 → 정비 요청
```

## 주요 기능

| 기능 | 내용 |
|---|---|
| 미션 관제 | 가상 발전소의 비행 경로, 진행률, 셀 상태 표시 |
| 핫스팟 분석 | 열화상 사진에서 핫스팟 후보와 마스크 표시 |
| 셀 판정 | 모델 결과 0(핫스팟 없음)과 3(핫스팟 탐지)으로 구분 |
| 사람 확인 | 후보를 근거 사진과 함께 승인 또는 제외 |
| 재점검 | 주의 또는 미확정 셀만 골라 재비행 미션 구성 |
| 체험 모드 | 로그인 없이 저장된 미션 결과 재생 |

셀 판정은 학습된 값이 아니라 규칙 기반입니다. AI 결과는 참고용이며, 최종 판단은 사람이 합니다.

## 시스템 구조

```text
웹 플랫폼 ── 미션 업로드 ──→ ArduPilot SITL
  ↑   │     ←─ MAVLink 위치·상태 ──┘
  │   │                     │ MISSION_ITEM_REACHED
  │   │                     ↓
  └───┼ 이미지 + 셀 정보 ── RPi 모사 프로그램
      │
      ↓
AIStream 서빙 (태양광 결함 분할 모델)
```

| 구성 요소 | 역할 | 위치 |
|---|---|---|
| 웹 플랫폼 | 관제 화면, 분석 결과, 사람 확인 | 팀 서버 |
| ArduPilot SITL | 비행 시뮬레이션 | 팀 서버 |
| RPi 모사 프로그램 | 웨이포인트 도착 시 사진 전송 | 팀 서버 |
| AIStream 서빙 | 핫스팟 탐지 | 전남 AI 오픈플랫폼 |

SITL을 사용할 수 없는 환경에서는 저장된 비행 기록을 재생합니다.

## 웹 대시보드 개발 가이드

드론과 모델이 준비되지 않아도 개발할 수 있도록, 먼저 가짜 데이터로 전체 화면을 만듭니다. 화면 구성은 [기획 문서](system-scenario-plan.md)의 1장을 참고하세요.

### 화면

| 우선순위 | 화면 | 내용 |
|---|---|---|
| 필수 | 대시보드 | 가상 발전소 격자 6×4(`A-1`~`D-6`), 셀 상태, 미션 시작 버튼 |
| 필수 | 미션 수행 | 드론 위치, 비행 경로, 진행률, 최근 사진, 분석 중 표시 |
| 필수 | 셀 상세 | 열화상 사진, 마스크 겹쳐 보기, 후보별 승인·제외 |
| 필수 | 결과 | 금전 가치, 공공 가치, 다음 조치, 재점검 대상 |
| 가능하면 | 3D 드론 창 | 위치 값으로 드론과 패널 표시 |
| 가능하면 | 보고서 | 확인된 결과로 초안 생성 |

첫 화면에 로그인 없는 "미션 체험하기"를 두어 저장된 비행 기록을 재생합니다.

### 데이터 형식 (초안)

드론 담당, 모델 담당과 맞춰 확정합니다.

```json
{
  "frame": {
    "mission_id": "mission_01",
    "cell_id": "C-4",
    "waypoint": 12,
    "source_photo": "photo_001.jpg",
    "position": { "x_m": 40.0, "y_m": 20.0, "rel_alt_m": 30.0 },
    "battery": 78
  },
  "analysis": {
    "source_photo": "photo_001.jpg",
    "hotspots": [{ "id": "h1", "bbox": [10, 20, 8, 6], "area_px": 42, "area_m2": 0.08 }],
    "mask_path": "masks/photo_001.png"
  },
  "cell": {
    "cell_id": "C-4",
    "status": "check",
    "candidate_count": 3,
    "confirmed_count": 0
  }
}
```

`status`는 `pending`, `no_candidate`, `caution`, `check`, `retake` 중 하나입니다. `bbox`는 `[x, y, width, height]`입니다.

### 셀 상태 규칙

모델 결과는 0 또는 3이고, 화면은 두 가지로 표시합니다.

| 모델 결과 | 모델 상태 | 화면 표시 | `status` |
|---|---|---|---|
| 0 | `no_hotspot_detected` | 핫스팟 없음 | `no_candidate` |
| 3 | `hotspot_localized` | 핫스팟 탐지 | `check` |

`caution`과 `retake`는 화면 코드에 남아 있지만 지금은 쓰지 않습니다.

### 금전·공공 가치

사람이 승인한 핫스팟이 있는 셀만 계산합니다. 승인 전에는 "확인 후 계산"을 표시하고, 승인·제외를 누르면 값을 바로 다시 계산합니다.

```text
회수 가능 전력량 = 셀 용량 × 8,760시간 × 이용률 × 출력 저하율
금전 가치 = 회수 가능 전력량 × 판매 단가
공공 가치 = 회수 가능 전력량 × 탄소 계수
수리비 회수 기간 = 수리비 ÷ 연간 금전 가치
```

- 모든 계수는 화면에서 수정할 수 있는 가정값으로 둡니다.
- 출력 저하율은 낮음·기준·높음 값을 받아 범위로 표시합니다.
- 값에는 항상 "추정"을 표시합니다.

### 구현 시 지킬 것

- **서빙 호출:** 브라우저에서 직접 호출하지 않고 백엔드에서 호출합니다. 서빙 URL은 `.env`에 둡니다.
- **민감정보:** 실제 GPS, 기체 일련번호를 화면과 API 응답에 넣지 않습니다. 사진은 메타데이터를 제거한 뒤 내려줍니다.
- **표시:** 화면에 "시뮬레이션"을 항상 표시합니다. "이상 없음" 대신 "탐지된 후보 없음"을 씁니다.
- **공개 주소:** 경로가 붙은 주소에서 열릴 수 있으므로 정적 파일과 API는 상대 경로로 호출합니다.
- **실시간 연결:** WebSocket이 공개 주소에서 막히면 주기적 조회로 바꿀 수 있게 구현합니다.
- **장애 대비:** 서빙 호출이 실패하면 저장된 결과를 표시합니다.

### 완료 기준

1. 로그인 없이 공개 URL에서 저장된 미션을 처음부터 끝까지 볼 수 있습니다.
2. 후보를 승인·제외하면 셀 상태와 금전·공공 가치가 바뀝니다.
3. 재점검 대상 셀을 고를 수 있습니다.
4. 휴대폰에서도 결과를 볼 수 있습니다.

작업 방법은 [협업 규칙](CONTRIBUTING.md)을 따릅니다.
