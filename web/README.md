# 대시보드 첫 화면

Node.js 20 이상에서 추가 패키지 설치 없이 실행합니다.

```bash
node tools/serve.mjs
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 포트는 `PORT` 환경 변수로 바꿀 수 있습니다. 기본 바인딩은 로컬 컴퓨터만 접속 가능한 `127.0.0.1`입니다. 이 서버는 개발 미리보기용이며 공개 서비스 배포용이 아닙니다.

## 구현 범위

- 밝은 테마와 상태별 색상·기호, 데스크톱 사이드바·모바일 접이식 메뉴
- 점검 현황 / 선택 점검 / 금전·공공 가치 / 점검 보고서 / 미션 기록을 메뉴별 화면으로 표시
- 메뉴 전환과 뒤로가기 시 메모리의 점검·후보 확인·입력값 유지 (새로고침 시에는 초기화)
- 6×4 구역 지도, 상태 요약, 선택 구역 안내
- 로그인 없는 합성 데이터 미션 재생, 일시정지, 이어서 재생, 초기화, 속도 조절
- 지그재그 경로와 현재 분석 구역, 진행률, 예시 배터리, 최근 이벤트
- 작은 화면 대응과 키보드 구역 선택

합성 데이터 프로토타입입니다. 선택 구역의 ‘이미지 · 후보 확인’에서 합성 도식, 결함 영역 표시 전환, 후보 선택, 승인·제외·미확인 전환을 사용할 수 있습니다. 실제 사진·AI 분석 결과·실기체 연결, 서버 저장, 실제 재점검 실행은 아직 구현하지 않았습니다. 지도·후보 개수·면적·경과 시간·배터리는 모두 예시이며 실측값이 아닙니다. 예시의 경과 시간은 재생 속도에 따라 빨라집니다.

사람의 확인 결과는 원래 탐지 상태를 덮어쓰지 않고 따로 집계합니다. 모두 제외해도 ‘탐지된 후보 없음’으로 바꾸지 않습니다. 승인 수는 `confirmed_count`에 반영하며 확인 기록은 구역별로 분리됩니다. 새로고침·미션 초기화·완료 후 다시 재생 시 확인 기록이 초기화됩니다. 사람 확인 상태는 지도·선택 카드·상세·보고서에 별도로 반영합니다. 탐지 등급 재판정과 서버 저장 규약은 팀과 확정한 뒤 연결합니다.

## 파일과 연결 지점

- `index.html`: 화면 구조
- `styles.css`: 데스크톱/모바일 스타일
- `theme-light.css`: 밝은 테마, 상태 강조, 사이드바 레이아웃
- `navigation.mjs`: 해시 주소 기반 화면 전환. 각 화면을 DOM에 유지하고 숨김 상태만 변경합니다. 지도는 기존 ResizeObserver로 복귀 시 경로를 다시 그립니다.
- `mission.mjs`: 합성 시나리오와 상태 전이. README의 `cell_id`, `status`, `candidate_count`, `confirmed_count` 형식을 사용합니다. 향후 백엔드가 반환하는 상태를 연결합니다.
- `app.mjs`: 표시와 사용자 조작. 모델 호출은 하지 않습니다.
- `detail.mjs`: 상세 dialog와 합성 도식·후보 조작. 원본 사진이 아닌 SVG 도식입니다.
- `review.mjs`: 합성 후보와 승인·제외 집계. AI 예측값 또는 정답 라벨로 사용하지 않습니다.
- `../tools/serve.mjs`: `web/`만 제공하는 개발 서버

사진 및 API 연결 시 상대 경로를 유지하고, 실제 사진의 메타데이터 제거는 백엔드에서 처리합니다. 미션 결과는 메모리에만 존재하며 새로고침하면 초기화됩니다. 임의의 후보 크기 임계값은 넣지 않았으며 상태는 명시적인 예시 시나리오입니다.

## 검증

```bash
node --test tests/mission.test.mjs tests/review.test.mjs
```

브라우저에서는 미션 완료, 일시정지 후 이어서 재생, 초기화, 구역 선택, 경로 표시 전환과 모바일 레이아웃을 확인합니다.

작업은 기능 브랜치에서 진행하고, 확인한 파일만 커밋합니다. GitHub의 PR로 합친 `main`만 팀 서버에 배포합니다. 원본 사진·데이터·실제 좌표·자격 증명은 포함하지 않습니다.

## 선택 점검

선택 점검 메뉴는 `사용자 지정`으로 시작하며, 점검 대기 여부와 관계없이 모든 구역을 직접 추가·해제할 수 있습니다. 전체 해제와 예시 선택 확정을 제공합니다. 사진 확보 필요·미확인 후보·승인한 주의 구역을 추천하며, 후보를 모두 제외한 구역은 추천에서 빠집니다. 승인만 남은 점검 권장 구역은 정비 판단 대상이므로 자동 재점검 추천에서 제외하지만 직접 선택할 수 있습니다. 이는 시제품 규칙이며 운영 임계값은 아닙니다.

추천 기준 기록을 선택하면 현재 선택을 해당 기록의 추천 목록으로 교체합니다. 불러온 뒤에도 모든 구역을 직접 추가·해제할 수 있습니다. 별도의 추천 대상 선택 버튼은 없습니다. 후보 승인·제외 시 추천 이유만 갱신하고 선택은 유지하며, 확정은 해제하여 다시 확인하도록 합니다. 선택 목록은 기존 예시 경로 순서로 표시되며 최적 비행 경로가 아닙니다. 새로고침·초기화·다시 체험하기는 선택을 지웁니다. API 전송과 서버 저장은 아직 없습니다. 선택 구역 재비행은 아래의 시뮬레이션으로 연결합니다.

`reinspection.mjs`에 추천 기준·선택 목록·화면을 모았습니다. `node --test tests/*.test.mjs`로 전체 테스트를 실행합니다.

## 선택 구역 재비행 시뮬레이션

전체 미션 완료 → 선택 점검 → 선택 확정 → ‘선택 구역 재비행 시작’ 순서로 재생합니다. 확정한 구역만 기존 지그재그 순서로 방문하며 별도 진행률·방문 목록·예시 촬영 단계가 표시됩니다. 일시정지·재개·1/2/4배속·재비행 초기화·같은 구역 다시 재비행을 지원합니다. 진행/일시정지 중 대상 변경은 잠기고, 초기화하면 다시 선택할 수 있습니다.

재비행은 `reflight.mjs`의 독립 상태로 관리합니다. 첫 미션·탐지 상태·사람 확인 결과를 덮어쓰지 않습니다. 후보 확인이 바뀌어도 이미 출발한 방문 목록은 유지되며, 다음 출발 전 다시 확정해야 합니다. 전체 미션 초기화·다시 체험하기는 재비행 타이머와 선택도 지웁니다. 새 사진·AI 결과·실제 비행 명령은 만들지 않습니다. C-6 예시 촬영 완료도 원래 ‘재촬영 필요’ 판정을 자동 해소하지 않습니다. 실제 재점검 결과 연결은 후속 작업입니다.

## 승인 기준 금전·공공 가치

승인 후보가 하나 이상 있는 구역만 중복 없이 계산합니다. 승인 전/승인 취소 후에는 ‘확인 후 계산’을 표시합니다. 동일 구역에 여러 후보를 승인해도 용량은 한 번만 포함합니다. 탐지 상태는 기존대로 보존합니다.

모든 가정값(구역당 kW 용량, 이용률 %, 판매 단가 원/kWh, 탄소 계수 kgCO₂e/kWh, 구역당 수리비 원, 낮음·기준·높음 저하율 %)을 수정할 수 있습니다. 기본값은 검증된 시장·공식 값이 아닌 계산 시연용입니다. README 계산식으로 세 시나리오의 연간 전력·금전 가치·탄소 감축 잠재량·단순 수리비 회수 기간(년)을 표시합니다. 총 수리비는 승인 구역 수 × 구역당 수리비입니다.

빈 값·음수·비유한 값·100% 초과 비율·뒤집힌 시나리오 순서는 계산을 차단합니다. 연간 금전 가치가 0이면 회수 기간은 계산 불가입니다. 수리로 가정한 손실을 모두 회수하는 잠재량이며 통계적 신뢰구간이나 실제 실적이 아닙니다. 가정값은 현재 페이지에만 유지되며 새로고침/예시 가정값 복원 시 기본값으로 돌아갑니다. 미션 초기화는 승인 기록을 지우지만 입력 가정값은 유지합니다.

계산과 화면은 value.mjs에 있으며 서버/API 규약에는 변경이 없습니다.


## 점검 보고서 초안

‘현재 결과로 보고서 만들기’에서 생성 시점의 점검 상태, 후보별 승인·제외·미확인 기록, 낮음·기준·높음 가치 추정과 모든 가정값·계산식을 고정한 미리보기를 엽니다. 미완료 미션은 부분 결과, 승인 전은 확인 후 계산, 잘못된 가정값은 추정 계산 불가로 표시합니다. 변경 후 다시 생성하면 최신 값이 반영됩니다.

HTML 보고서 다운로드는 외부 전송 없이 브라우저에서 독립 파일을 생성합니다. 파일은 외부 스크립트·스타일·이미지 의존성이 없어 인터넷 없이 열 수 있습니다. 브라우저 인쇄에서 PDF로 저장할 수 있도록 A4 인쇄 스타일을 포함합니다. 실제 사진·AI 결과·정답 라벨이나 실제 비행 기록이 아닌 합성 예시임을 명시합니다. 재비행은 새 분석을 만들지 않으므로 기존 점검 결과를 보고합니다.

report.mjs가 보고서 생성과 다운로드를 담당합니다. detail.mjs의 candidates(cell)과 value.mjs의 assumptions()를 읽기 전용 연결점으로 사용합니다. 서버/API 변경은 없습니다.


## 후보 확인에 따른 셀 상태

지도와 선택 카드, 셀 상세는 미확인 후보 있음 → 승인 후보 있음 / 후보 모두 제외 상태를 표시합니다. 일부 후보만 처리했으면 미확인 상태를 유지합니다. 모든 후보를 처리하고 하나 이상 승인했으면 승인 후보 있음, 전부 제외했으면 회색 후보 모두 제외가 됩니다. 미확인으로 되돌리거나 미션을 초기화하면 상태도 복원됩니다.

원래 status, 후보 수, 미션 기록은 변경하지 않습니다. 모두 제외를 ‘탐지된 후보 없음’으로 재분류하지 않습니다. 확인 필요 요약은 미확인/승인 구역만 세고, 모두 제외는 지도 아래 따로 표시합니다. 원래 탐지 등급 색상은 유지하며 모두 제외만 회색으로 표시합니다. 보고서는 원래 탐지 상태와 현재 사람 확인 상태를 함께 기록합니다. 가치 추정과 재점검 추천은 기존 승인·제외 기준을 유지합니다.

cell-review-status.mjs가 상태 계산·화면 표시를 담당합니다. app.mjs의 render 끝에서 표시 함수만 호출하며 미션·재비행 로직은 수정하지 않습니다. 승인 후 후보 크기/개수에 따른 탐지 등급 자체의 재판정은 멘토 기준 확정 전까지 하지 않습니다.

## SITL 3D 비행

점검 현황의 지도 카드에서 `3D 비행`과 `2D 지도`를 전환합니다. `sitl.mjs`와 `flight.mjs`가 `GET ./api/missions/mission_01`의 ArduPilot SITL 비행 기록을 3D 화면, 비행 상태, 비행 로그로 보여 줍니다. API가 필요하므로 `node server/index.mjs`로 실행합니다. `tools/serve.mjs`처럼 기록을 받지 못하면 2D 지도로 돌아갑니다.

`app.mjs`가 보내는 `mission:change` 이벤트로 미션 재생과 연동되어, 드론과 지도가 같은 구역에 머뭅니다. 드론 값은 기록을 따르지만 재생 시간은 미션 속도에 맞춰 빠르게 돌립니다. 셀 색은 2D 지도와 같은 예시 판정입니다.

## 점검 현황

메뉴는 `점검 현황(드론 연동)`만 사용합니다. 서버의 SITL을 8배속으로 켜고 비행을 시작하며, 드론이 도착한 구역부터 예시 판정이 표시됩니다. 비행 기록은 `live.jsonl`이고 저장소에 올리지 않습니다.

오른쪽 열 맨 위의 비행 계기(`hud.mjs`)는 같은 비행 기록으로 수평계, 방위, 대지속도, 고도를 그립니다. 롤과 피치는 `mission.py`가 기록한 비행 제어기의 `ATTITUDE` 값을 쓰고, 이 값이 없는 예전 기록과 계산 경로에서는 위치 변화로 계산한 근사값을 씁니다. 카드 제목 옆에 어느 값인지 표시합니다.

오른쪽 열은 점검 미션, 촬영 이미지, 비행 계기, 드론 로그 순이며 점검 미션을 뺀 카드는 제목 줄의 화살표 버튼으로 접을 수 있습니다(`side-cards.mjs`, 접힘 상태는 이 브라우저에만 저장). 촬영 이미지는 드론이 마지막으로 도착한 구역의 합성 열화상(`detail-assets.mjs`)이며 실제 촬영 사진이 아닙니다. 이미지를 누르면 구역 상세가 열립니다.

`점검 현황(데모)`는 꺼 두었습니다. `index.html`의 메뉴에 `<a href="#overview">` 링크를 되돌리면 저장된 기록을 재생하는 데모가 다시 켜집니다.

재점검의 `선택 구역 재비행 시작`은 고른 구역으로 SITL 비행을 시작하고, 재점검 진행과 3D는 그 비행 기록을 따라갑니다. SITL 비행은 멈출 수 없어 재비행 중에는 일시정지와 초기화가 꺼집니다. SITL이 꺼져 있거나 다른 비행 중이면 시작하지 않고 안내만 표시합니다.

기록의 시간은 현실 초이고, 화면의 비행 시간과 로그 시간은 배속을 곱해 비행 기준으로 표시합니다. 넓은 화면에서는 지도 카드가 고정되고 오른쪽 열이 스크롤됩니다.

제어 API(`POST /api/sitl/start|stop|fly`)와 상태 조회(`GET /api/sitl/status`)는 누구나 쓸 수 있습니다. SITL 끄기는 5초 안에 다시 눌러야 하고, 비행은 동시에 하나만 실행됩니다. 공개 주소의 누구나 SITL을 끌 수 있으므로 시연 중 끊길 수 있습니다. 배속은 `SITL_SPEEDUP`(기본 8)으로 바꿉니다.

## 핫스팟 모델 연결

드론이 구역에 도착하면 화면이 `GET ./api/predict/{구역}`을 부르고, 웹 서버(`server/predict.mjs`)가 그 구역의 열화상 사진을 모델 서빙(`POST /predict`, multipart `file`)으로 보냅니다. 서빙 도메인은 브라우저 요청(CORS)을 받지 않아 서버를 거칩니다.

- **`PHOTO_DIR`:** 열화상 사진 폴더입니다. 예: `/data/test`. 하위 폴더까지 jpg, png만 찾으므로 AI Hub의 `TS_*`(사진)는 쓰고 `TL_*`(라벨 JSON)는 건너뜁니다. 사진 목록은 1분마다 다시 읽습니다. 새 전체 비행을 시작할 때마다 구역마다 사진을 무작위로 다시 고릅니다. 사진이 충분하면 겹치지 않고, 모자라면 겹칩니다. 재비행은 같은 비행의 사진을 그대로 씁니다. `A-1.jpg`처럼 구역 이름으로 된 사진은 항상 그 구역에만 씁니다.
- **시연용 핫스팟 보장:** 전체 비행마다 앞쪽 두 줄(A·B행) 중 한 구역에 이름에 `positive`가 들어간 폴더의 사진(AI Hub `TS_*_Positive_*`)을 배정합니다. 모델이 핫스팟으로 판정하지 않으면 다른 Positive 사진으로 바꿔 최대 5번까지 다시 판정합니다. 폴더 이름 기준은 `HOTSPOT_PHOTO_PATTERN`(기본 `positive`)으로 바꿀 수 있습니다. 나머지 구역은 무작위입니다.
- **`MODEL_URL`:** 기본 `https://aiopen-serving.jntp-ax.or.kr/jntp-gpu/SV-fc7f6908/predict`입니다.
- **판정:** `is_hotspot`이 true면 핫스팟 탐지(후보 수 = 모델 영역 수), false면 핫스팟 없음(후보 0)입니다. 결과가 올 때까지 셀은 대기로 남습니다.
- **새 비행:** 새 전체 비행이 시작되면 보고 있는 모든 화면에서 셀, 진행률, 지도가 대기로 초기화되고 도착한 구역부터 다시 채워집니다.
- **촬영 이미지 카드:** 모델이 돌려준 결과 이미지(`output`)와 점수, 영역 수를 보여 줍니다. 점수는 보정 전 값입니다.
- **결과 저장:** 같은 사진의 결과는 서버 메모리에 저장해 다시 호출하지 않습니다. 실패한 호출은 다음 도착 때 다시 시도합니다.
- **연결이 안 될 때:** `PHOTO_DIR`이 없거나 모델 호출이 실패하면 그 구역은 예시 판정과 합성 이미지로 표시됩니다. `GET ./api/predict`로 설정 여부와 사진 수를 확인합니다.
- **구역 상세 창:** 모델로 판정한 구역은 원본 열화상(`GET ./api/photo?name=`)에 모델 영역(bbox)을 하늘색 상자로 그립니다. 결함 영역 표시를 켜면 모델 결과 이미지(`GET ./api/overlay?name=`)를 겹칩니다. 후보는 모델 영역(면적, 점수)이고, 고른 후보는 흰색 상자로 강조됩니다. 셀에는 사진 이름과 영역만 저장하므로, 지난 기록을 열어도 그때 사진이 나옵니다. 두 API는 사진 폴더에 있는 파일만 돌려줍니다. 모델 결과가 없는 구역은 지금처럼 합성 예시를 씁니다.

## 비행별 점검 기록
점검 기록은 셀별 이벤트 대신 비행 시작을 화면에서 관측한 한국 날짜·시간별 한 행으로 저장합니다. 행을 누르면 해당 기록의 2D 지도와 기존 셀 상세(합성 열화상, 마스크, 후보 확인)가 열립니다. 과거 기록에서 승인·제외한 결과는 그 기록에만 저장됩니다.
기록은 서버의 inspection-history.json에 누적됩니다. 서버가 실행 중이면 브라우저 없이도 FLIGHT_DIR의 비행 파일을 주기적으로 수집합니다. 모든 접속자가 같은 기록과 후보 승인·제외 결과를 보며, 후보 단위 변경을 직렬 저장합니다. 기존 브라우저 localStorage 기록은 삭제하거나 자동 이관하지 않습니다. 실제 촬영 사진 저장은 아직 지원하지 않으며 합성 예시를 재현합니다.

선택 점검의 `추천 기준 기록`에서 날짜·시간별 전체/재점검 기록을 선택할 수 있습니다. 진행 중 기록은 제외하며, 선택 기록의 방문 완료 구역과 현재 저장된 후보 승인·제외 상태로 추천합니다. 기록 변경 시 해당 기록의 추천 구역을 자동 선택하고 확정은 해제합니다. `사용자 지정`으로 돌아가면 선택을 비웁니다. 현재 점검 상태를 덮어쓰지 않으며, 새로고침 후에도 저장 기록으로 대상을 정할 수 있습니다.

## 서버 공용 기록과 기록별 분석

- `GET ./api/inspection-history`: 서버 공용 목록. `PATCH`는 `id`, `cellId`, `candidateId`, `decision`으로 후보 하나의 승인·제외·미확인을 저장합니다. 진행 중 비행의 확인 변경은 완료 후 가능합니다.
- 저장 위치는 기본 `FLIGHT_DIR/inspection-history.json`, 별도 영구 볼륨은 `HISTORY_FILE` 절대경로로 지정합니다. JSON 및 임시 저장 파일은 Git에 포함하지 않습니다. 단일 Node 서버 프로세스 기준입니다. 배포 시 저장 파일을 유지해야 누적 기록이 유지됩니다.
- 비행 원본에는 절대 시작 시각이 없으므로 날짜는 서버 파일 생성 시각(한국 시간)입니다. 복사한 샘플은 실제 비행 날짜를 뜻하지 않습니다. 기존 파일도 한 번 수집하며 새 live 파일을 덮어쓰기 전에 이전 기록을 보관합니다. 서버 중단 중 이미 사라진 비행 파일은 복원할 수 없습니다.
- 점검 분석은 완료·중단 기록 중 날짜를 선택합니다. 그 비행의 방문 완료 구역 중 승인 후보가 하나 이상인 구역만 계산합니다. 미확인/제외만 있으면 분석 대상 없음이며 수치를 표시하지 않습니다. 동일 구역의 여러 승인은 용량을 중복 계산하지 않습니다.
- 하루 발전량 예측 = 구역당 용량 × 24 × 이용률. 실측 비교값은 날짜·구역으로 고정한 3~12% 손실을 적용한 더미입니다. 실제 계량/모델 예측이 아닙니다. 이 일간 비교와 별도의 저하율 가정에 따른 연간 회수 가치 시나리오는 서로 다른 계산입니다.
- 점검 보고서는 기존 현재 점검 스냅샷을 사용합니다. 선택한 과거 기록의 분석 보고서 내보내기는 아직 연결하지 않았습니다.
점검 기록 행에 마우스를 올리거나 키보드로 이동하면 오른쪽에 삭제 버튼이 나타납니다. 터치 환경에서는 항상 표시됩니다. 확인 후 DELETE /api/inspection-history로 서버 공용 목록에서 제외하며, 삭제 표시를 보관해 원본 비행 파일이 다시 수집되지 않도록 합니다. 진행 중인 기록은 삭제할 수 없습니다. 원본 비행 파일은 지우지 않습니다.

### 점검 기록의 모델 결과 저장

`GET /api/predict/{구역}`의 성공 응답은 요청 시작 시점의 `live.jsonl` 비행 기록에 연결해 저장합니다. 방문한 대상 구역만 저장하며 사진 이름, 점수, 영역, 결과 이미지를 보존합니다. 같은 기록에 이미 저장한 모델 결과와 승인·제외는 반복 요청으로 덮어쓰지 않습니다. 합성 후보에서 실제 모델 후보로 처음 바뀔 때는 승인·제외를 미확인으로 시작합니다.

기록 상세는 저장한 사진 이름으로 원본을 읽고, 저장한 결과 이미지를 사용합니다. 원본 사진은 `PHOTO_DIR`에 같은 이름과 내용으로 보관해야 합니다. 사진 파일이 없어지면 로딩 실패를 표시하며 합성 이미지로 바꾸지 않습니다. 과거 기록에 사진 매핑이 없으면 복원할 수 없으며 기존 합성 기록임을 표시합니다. 모델 응답을 받지 않은 구역은 자동으로 실제 결과가 되지 않습니다. 현재 진행/완료된 live 기록은 점검 현황에서 모델 응답을 다시 받으면 저장할 수 있습니다.

선택 점검도 서버의 `prediction-recorder.mjs`가 현재 `live.jsonl`에서 방문한 셀을 수집해 모델 결과를 기록에 저장합니다. 점검 현황 화면의 `/api/predict` 호출이 없어도 동작합니다. 이미 저장한 결과·확인 기록과 미방문 셀은 변경하지 않으며, 이전 비행은 재분석하지 않습니다. 모델 호출 실패는 10초 뒤 재시도하며 저장된 실제 결과로 표시하지 않습니다. 드론 제어·사진 배정 방식은 기존 동작을 유지합니다.
